# Research — Kick Focus
Date: 2026-08-16 — replaces all prior research (prior pass was 2026-08-15 against v1.5.0; every headline opportunity it named — quality persistence, emote catalog reads, multi-stream, realtime transport swap, collectible rarity, shadowed-name detection, chat pause, per-channel notes, DNR initiator scoping — shipped across v1.6.0–v1.9.0).

## Executive Summary

Kick Focus at v1.9.0 is a genuinely zero-dependency, single-author kick.com client mod (63 commits over two calendar days) that builds four artifacts — a userscript, an MV3 Chromium package, an MV2 Firefox package, and two zips — from one hand-rolled concatenation of `src/core.mjs` + `api.mjs` + `compatibility.mjs` + `runtime.js` (`scripts/build.mjs`; no bundler, no `node_modules`, no lockfile, no `@require`/`@resource`, no `externally_connectable`). It ships a shadow-DOM settings center (five pages, ~90 controls), content/ad filtering backed by two DNR rulesets generated from 8 ad + 3 telemetry hosts, a nine-tile multi-stream grid with shareable `?kf-multi=` layouts, a schema-5 recorded emote library (favorites, custom groups, Kick-edit change detection) capped at 2,400 entries, an opt-in remote blocklist over three transports, and es/pt localization (211 keys/locale). Its strongest current shape is the read-only, same-origin, fails-back-never-fails-open API posture and the on-origin multi-stream grid built on Kick's own embeds — a compliance moat no competitor in this space holds. Its weakest shape is verification: 96 offline checks and 84 unit tests are all green, but **no offline gate ever executes the product** and the one behavioral gate (`verify-extension.mjs`) exits 0 having verified nothing because no Chromium exists on this machine — so nothing at HEAD proves the extension loads, blocks a request, or renders a page (README:138 even claims a live Chromium proof the repo's own tracker says is impossible).

The highest-value direction is operator-demand-driven, then the data-safety/security/verification cluster the audit surfaced. Top opportunities, in priority order:

1. **[OPERATOR FLAGSHIP] Realtime chat-emote harvest** — "scan chats to collect emotes." Realtime frames already carry `.emotes [{id,name}]` per message and discard them; ~6 runtime lines + one pure core function turn the single biggest untapped collection channel on. *Demand-driven.* (R-06.)
2. **[OPERATOR FLAGSHIP] One-click "Add to Multi" from channel pages** — "one-click Multi from the video page." A third header button + card chips, on top of already-tested core functions. *Demand-driven.* (R-07.)
3. **Single highest-leverage action: `npx playwright install chromium`.** One uninstalled binary is the sole gate between "green having proven nothing" and ~18–22 real live assertions, the `runtime.js` split, and four blocked ROADMAP items. A coding agent can run it now. (R-01.)
4. **Fix the emote-library cap** — at 2,400 the library discards every *new* emote forever and rewrites the whole ~0.5 MB store every scan cycle; "Remove" never frees a slot. (P0; operator precondition for R-06.) (R-02.)
5. **Fix Reset** — "Reset all settings" destroys the irreplaceable emote library (with provenance the product calls its only proof Kick edits emotes) while failing to clear 8 private stores. (P0.) (R-03.)
6. **Fix Export omissions** — 4 of 8 named stores (incl. private channel notes) have no backup path while the UI says export is the only way to save them. (P0.) (R-04.)
7. **Harden every privileged fetch/transport path** — an arbitrary-HTTPS fetch-forgery + response-exfiltration channel, an unauthenticated telemetry-ruleset toggle + storage write, a page-writable "protection active" claim, and a cookie-leaking userscript blocklist fetch. (P0.) (R-05.)
8. **Resolve the telemetry-strategy contradiction (litix.io)** — the companion DNR ruleset hard-cancels the exact host whose blocking causes a documented 139k-request retry storm and "massive delays entering live streams." (P1; now actionable — external evidence stands in for the multi-hour measurement that blocked it.) (R-08.)
9. **IVS player ad-break observability** — Kick's own IVS Web Player SDK emits first-party `AD_BREAK_STARTED/ENDED` events; a read-only listener yields an authoritative ad-break indicator without touching the manifest or WASM worker. Supersedes the worker-wrapper item. (P1.) (R-09.)
10. **Add a boot-execution gate** — no test imports `runtime.js`; a TDZ read or bad `const` ordering across the four-module concat passes every offline gate. (P1.) (R-10.)
11. **i18n correctness + coverage** — the hand-built plural is wrong in *both* es and pt (CLDR 48 gives both a "many" category); ~83 strings never translate; ~30 toasts are permanently English. (P1.) (R-11.)
12. **Accessibility regressions on a product that ships an accessibility page** — whole-page `innerHTML` replacement drops focus and scroll on every toggle; forced-colors erases every selected state; toasts have no live region. (P1.) (R-12.)

## Product Map

**Core workflows (v1.9.0 reality):**
- **Restyle + focus** — one graphite-and-lime shell over Kick's semantic desktop DOM; Standard/Theater/Focus layouts; Auto/Compact/Dropdown/Hidden discovery rail; a panic switch that restores native Kick without reload.
- **Emote library** — schema-5 records from three live feeds (open-picker scrape, chat-DOM scan, per-channel API catalog with real entitlement), capped at 2,400; favorites shelf, custom groups, Kick-edit change detection via `firstSeen`/`wasName`/`wasSrc` provenance; JSON export/import.
- **Multi-stream** — up to nine channels in one on-origin grid built on Kick's own embedded player + popout chat; audio/chat follow the focused tile; named layouts; shareable `?kf-multi=` links; reachable from header control, command menu, or settings.
- **Content/ad defense** — page-realm `fetch`/XHR/beacon/dynamic-element hooks + `/playback` ad-flag rewrite; optional companion adds `declarativeNetRequest` network-layer blocking (8 ad + 3 telemetry hosts, `initiatorDomains:['kick.com']`).
- **API reads** — read-only, same-origin, session-inherited: emote catalog with entitlement, realtime chat over the broker-named provider (Pusher or `websockets.kick.com`), removed-message reasons, per-channel/global usage counts, collectible rarity, shadowed-name reporting; each degrades to DOM behavior and has its own switch.

**Personas:** the privacy-and-calm desktop Kick viewer (restyle, filters, focus modes); the emote collector/power-chatter (library, favorites, the operator's harvest/autocomplete demands); the multi-channel viewer (grid, the operator's one-click-add demand). No mobile, no auth flows, no multi-step forms.

**Platforms & distribution:** desktop Chromium (userscript + MV3) and desktop Firefox (userscript + MV2). Node 22+ (`package.json:16`; `verify-extension.mjs` uses global `fetch`/`WebSocket`, ruling out the Node 20 figure `CLAUDE.md:7` still advertises). **No git remote, no tags, no CI, no store listing, no users** — every defect was found by self-audit, so gate quality carries the entire weight a user base would normally share. The userscript is the only artifact that reaches Windows/macOS users; the .crx cannot self-install off-Web-Store there, and Firefox needs AMO sign-without-listing.

**Key data flows:** eight `localStorage`/GM stores (settings, stickers, emote-usage, multistream, channel-notes, chat-keywords, media-preferences, channel-layouts, favorite-channels, not-interested-channels); page↔isolated-world DOM-event bridge for the MV3/MV2 companion (blocklist fetch, settings sync, telemetry toggle, companion presence); realtime WebSocket for chat; same-origin `/api/v2` reads.

## Competitive Landscape

- **NipahTV** (Kick; userscript + Chrome + Firefox from one TS source) — *does well:* published IndexedDB schema (`emoteUsages`/`favoriteEmotes` keyed `[platformId+channelId+emoteHid]` with `orderIndex`, six versioned migrations) that independently converged on KF's schema-5, and a `Proxy` marshalling one call-site API to three artifacts; proves `execCommand('insertText')` works on Kick's editor. *Learn:* the `platformId` key prefix is cheap forward-compat KF lacks (R-30); the Proxy-over-storage shape (R-29). *Avoid:* Dexie is a dependency — borrow schema/migration shape only.
- **FrankerFaceZ** — *does well:* `src/settings/providers.ts` — four priority-scored user-switchable storage providers (localStorage −1000, IndexedDB 10 with a separate blob store + `awaitReady`/`flush`, extension storage 101), a `quota-exceeded` event instead of silent failure, BroadcastChannel tab sync; a context-filter tree compiled to tester functions. *Learn:* the provider abstraction is the direct answer to KF's 2,400 cap and to FFZ #1026 (one 250k-char setting hard-failed a whole restore). Its picker uses IntersectionObserver placeholder-swap with **no most-used or recency ranking** (FFZ #971, #1725 — requested, never delivered) — the exact gap KF's existing per-channel usage counts fill (R-18). *Avoid:* addons.json dynamic-script-injection loader (remote code).
- **7TV** — *does well:* the field-standard colon autocomplete (`ChatInput.vue`) and favorite-from-chat. *Learn:* its Kick support runs on an unversioned 2025 nightly against a 2026 site (no tagged stable since v3.1.6, 2025-03-04) — a concrete opening for a maintained, drift-aware alternative; its picker has **no virtualization** despite v3.0.0 claims, validating KF's "no full virtualization" decision (R-18 / reject list). *Avoid:* third-party emote federation conflicts with KF's same-origin privacy posture — a documented decision, not silent (R-23).
- **BetterTTV** — *learn:* per-channel frequently-used bar; the `files.kick.com` vs `cdn.7tv.app` host-filter lesson (BTTV #5925) that keeps KF's DOM scan from ingesting 7TV-injected imgs (R-16).
- **Chatterino** — *does well:* a user-facing filter DSL over `author.*`/`message.*`/`channel.*`/`flags.*`; tab-completion with documented case-collision bugs (#1962/#3440) that are ready-made tests for KF's autocomplete ranking (R-25). *Avoid:* Lua runtime (remote code).
- **KickTalk / Kickerino / Kickplex** — *learn:* Kickplex moved multi-view past tiles to unified cross-channel chat, DVR rewind, PiP; its per-channel-scoped picker is precedent for R-26. Kickerino is an early-warning system for Kick API churn (shipped fixes for collectible-badge-in-chat, XSRF-dropped, and timeout/ban-delete behaviour within days of each). Every one carries pnpm/Vite/esbuild/Tauri/Electron — KF's dependency-free three-artifact build is uncontested.
- **PureKick / Kick-Ad-Blocker** — *learn:* PureKick has 20,000 users at 4.8/5 (v10.2.1 shipped 2026-08-15). But mainstream filter lists **do not cover Kick** — uAssets #33256 and AdguardFilters #233048 both declined to write rules; KF's page-realm `/playback` approach is genuinely ahead (short shelf life — document now, R-23). *Avoid:* naive `[data-testid*="ad"]` selectors false-positive on Kick's `identity-badge-subscriber` DOM (lurkloot #242).
- **Kick Quality Enforcer** (Chrome + Firefox, plus three Greasyfork scripts) — *learn:* quality persistence is the single most independently re-implemented Kick need. **KF already ships it** (`applyQualitySessionKey`, `QUALITY_SESSION_KEY`, `rememberQuality`) — this is a live-validation item, not a greenfield feature; the prior research's "most re-implemented gap" framing was overstated.
- **multitwitch / StreamGrid / MultiKick / viewgrid / KickTheater** — *learn:* the add-flow UX (URL/input typing) is the field's #1 complaint (viewgrid.tv), which is exactly the operator's one-click demand; StreamGrid's "save as layout" nudge (R-07); MultiKick keeps both a name-input and a one-click flow. *Avoid:* off-origin grids are the platform-hostility death pattern (Twitch parent-param breakage, drupal #3155349) — KF's on-origin Kick embeds are the moat.

## Security, Privacy, and Reliability

Grouped P0/P1 findings with file:line. Confidence: all code-verified (Verified) unless noted.

- **[P0] Bridge fetch-forgery + exfiltration (#5, Verified).** `document.addEventListener('kick-focus:fetch-blocklist')` forwards `event.detail.url` verbatim to a privileged background fetch validated only by `startsWith('https://')`, returning the full body via CustomEvent readable by any page script — an arbitrary-HTTPS request-forgery + response-exfiltration channel any kick.com script (Kick, injected ad, XSS, another MAIN-world extension) can drive; the URL is never pinned to `state.settings.content.blocklistUrl`. `src/extension/bridge.js:106-115`, `bridge.firefox.js:78-86`, `background.js:60-77`, `background.firefox.js:84-99`. **Fix:** pin the fetch to the configured URL.
- **[P0] Unauthenticated telemetry-toggle + storage write (#6, Verified).** `kick-focus:settings-changed` is `JSON.parse`d and passed unvalidated to `publish()` → `chrome.storage.local` + a **global, persistent** `updateEnabledRulesets` toggle; the popup then reports the attacker's state back as the user's own preference. `bridge.js:48-59,68-78`, `background.js:35-41`, `popup.js:58`. **Fix:** validate inbound payloads against the schema the project already owns.
- **[P0] Page-writable "protection active" claim (#7, Verified).** `companionInfo()` reads `document.documentElement.dataset.kickFocusCompanion`; a page script can set it (faking "Network + page · Ad requests are blocked before they are sent") or delete it (silent downgrade + blocklist transport misrouted). `runtime.js:173-176`, consumed at `:3728,5824,5828,5937,6545`. **Fix:** prove companion presence by round-trip, not attribute.
- **[P0→R-05] Cookie-leaking userscript blocklist fetch (Verified; memo §5B promoted to HIGH).** The userscript blocklist transport uses `GM_xmlhttpRequest` (`runtime.js:3748-3760`) with **no `anonymous:true`**, so under `@connect *` (`metadata.txt:19`) it sends the user's ambient cookies to any host — directly contradicting the settings copy "refreshes only over HTTPS with credentials omitted." `blocklistUrl` accepts any ≤2048-char string with **no scheme check** at normalize time (`core.mjs:211`), and an imported settings file can set it and start the refresh timer without further consent. **Fix:** `anonymous:true` on the GM fetch + https-scheme validation at normalize.
- **[P0] Library cap discards-new + rewrite-loop (#8, Verified).** `cleanStickerLibrary` `break`s at 2,400 in insertion order (keeps oldest, drops **newest**); `runtime.js:1608-1613` re-reads the truncated value; every next cycle re-sets the emote → `changed` → full ~0.5 MB `setItem`, forever. Reaching 2,400 is ordinary use (`organizeChatStickers` default true). Library "Remove" never frees a slot (`runtime.js:6106-6122`). `core.mjs:787-788`, `runtime.js:3089-3126,3175-3200,5656-5661`.
- **[P0] Reset destroys the irreplaceable, keeps the private (#4, Verified).** "Reset all settings" → `resetStickerPreferences()` (`keepLibrary:false`) deletes up to 2,400 records incl. unregenerable provenance, unmentioned in confirm copy — while failing to clear 8 private stores (channel-notes, emote-usage, chat-keywords, media-preferences, channel-layouts, favorite-channels, not-interested-channels, multistream). `runtime.js:6399-6405,3534-3552,2-12`.
- **[P0] Export omits 4 of 8 named stores while claiming otherwise (#11/#12, Verified).** `exportSettings` writes `{...settings, stickers, usage, multistream}`; `STORAGE_LABELS` names 8; `renderStorageHealthPanel` says "Exporting now is the only way to keep these." Private channel notes have no backup path at all. Three build-written keys are absent from `STORAGE_LABELS` entirely. Fourth recurrence of this class with no gate. Import replaces the whole library/usage/multistream with no merge/backup/confirm. `runtime.js:6420-6429,5916-5931,6447-6489`, `core.mjs:1487-1496`. **Fix:** a single source-of-truth store registry + a gate asserting export covers it.
- **[P1] litix.io retry-storm contradiction (Now actionable, code-verified + external evidence).** litix.io **is** in `TELEMETRY_HOSTS` (`core.mjs:98`); the page realm answers blocked telemetry with empty-200 to avoid the storm (`runtime.js:307-310`, used at `:544`), but the companion DNR ruleset **hard-cancels** the same hosts — reintroducing it. uAssets #33860: blocking litix.io = 139,182-of-139,189 blocks on one domain; #34081: "massive delays when entering live streams." **Fix:** make the companion telemetry strategy match the page realm (don't hard-cancel litix.io) or drop it from the DNR telemetry ruleset. (R-08.)
- **[P2] `kCommitErrorThreshold` / 400-day durability threats (Verified, external).** Not a quota problem (Chrome = 10 MB; library ≈ 10–30% of budget). But `kCommitErrorThreshold=8` throws away the **entire origin's** localStorage after 8 consecutive commit errors, and `kLocalStorageStaleBucketCutoffInDays=400` makes an inactive key eligible for deletion — both silent, total, unrecoverable, no server copy. **Fix:** transactional import (stage → validate total serialized size → commit) so a mid-write failure can't half-apply (FFZ #1026). (R-21.)
- **[P3] Trusted Types future cliff (Needs live validation).** kick.com ships no CSP today (Observatory D/30, scan 2026-08-16), but Trusted Types reached Baseline 2026-02; a future `require-trusted-types-for 'script'` turns every page-world `innerHTML` write into a TypeError. Feature-detect and route through a policy. (R-31.)
- **DNR rule discipline (Verified, keep as a mechanical review rule).** Socket's April 2026 report found `declarativeNetRequest` used to strip security headers across 108 extensions; KF must stay **block-action-only, never `modifyHeaders`**. DNR rules already carry `initiatorDomains:['kick.com']` (`build.mjs:57`), so they are initiator-scoped, not browser-wide; `initiatorDomains` (request initiator) and the newer Chrome-145 `topDomains` (the tab's top-level domain) are **orthogonal axes** — `topDomains` is a possible refinement, not a fix for anything broken. Separately, `initiatorDomains` does match worker-initiated requests (Chrome docs), which validates the current worker-segment coverage and closes the roadmap's old open DNR question.
- **`__proto__` JSON-import DoS (Verified, second tier).** `__proto__` as a channel slug reparents the usage map (`core.mjs:1173-1178`); Node's 2026-03-24 release patched a related `__proto__` header-name DoS (CVE-2026-21710). Guard the import path (folded into R-04).

## Architecture Assessment

The five highest-leverage weaknesses (memo §3), with refactor candidates:

1. **`runtime.js` is the architecture, and it only grows.** 6,651 lines, +7,723/−640 lifetime (12:1), 1,694 at birth; no test executes a line of it; every UI state change is a full `innerHTML` re-render. Pure decisions still stranded and extractable today: `applyContentFilters`' five-way hide composition (`:3861-3864`), `localChannelBlocked`/`remoteBlocklistMatches` (`:3673-3688`), `cardContext` (`:2598`, already `FakeNode`-compatible), `activeLocale` (`:5330`). The project's own split pattern (`filterDecision`, `planMultistreamTiles`, `chatBadgesToRender` in core.mjs) proves the discipline exists and simply stopped being applied. **Blocking item for the split: one uninstalled binary (chromium).**
2. **Verification is append-only substring greps over generated text, and the single behavioral gate is optional.** `check.mjs` is ~+400/−8 lifetime; ~90 of ~96 checks are `source.includes()` on identifiers or literal CSS pixel values, asserting *presence of strings in output it just generated* rather than behavior. Eleven DNR network-rule checks pass green on an empty host list (`0===0`, `[].every()` true — the exact `CLAUDE.md:61` trap); two "stays on kick.com" exfil gates match 0 of either form because endpoints are template-interpolated (`${KICK_ORIGIN}/api/...`); `content_scripts[].matches` is gated on neither manifest (`<all_urls>` passes all 96 checks). `missingExports()` (`:36-47`) is the one gate that derives its list from source — the template, never reused. **Fix:** derive gate inputs from source; adopt `node:test` `expectFailure` for systematic red-verification. (R-13.)
3. **The page↔isolated-world bridge is an unauthenticated DOM-event channel carrying two privileged primitives, and trust flows the wrong way** (see Security #5/#6/#7). Correct shape: validate inbound against the owned schema, pin the fetch, prove presence by round-trip. (R-05.)
4. **Persistence has no normalize-on-read/write chokepoint, and the store list is hand-maintained in four divergent places** — `STORAGE_LABELS` (8), export payload (4), reset scope (2), key constants (11), all disagreeing. This is why the same data-loss class has been fixed four times on four surfaces (074beca, 4218de2, 18fb942, 5deaf3a) with no invariant gate, and why the cap drops the newest and `emoteUsage` is unbounded again on the next boot (#24). **Fix:** a single store registry + a persistence chokepoint. (R-04.)
5. **A two-target build by textual concatenation + verbatim file copy, with no per-target gate.** Load-bearing undocumented constraints: all 110 exports must match `^export (function|const|class)`; no `src` module may `import`; no top-level identifier may collide across four files. The Firefox target inherits files by `cp` with no Firefox gate — which is how a Chromium-only `popup.js` (promise-API `chrome.tabs.query`, dead on Firefox's callback alias) shipped in the Firefox zip (#9), and how `manifest.dev.json` (higher-privilege, `declarativeNetRequestFeedback`) ends up inside the release archive (#10). Three of eight scripts resolve paths against `process.cwd()` while five derive from `import.meta.url` — an undocumented invocation constraint. (R-14.)

**Test + docs gaps.** No offline gate executes the product (`node --check` parses the 9,038-line bundle and stops); `companion.test.js` already demonstrates the `vm.runInNewContext` + stubs fix at zero dependency cost (R-10). The MV3 primary target (`background.js`, `popup.js`, `popup.html`) has **zero** offline coverage; the MV2 secondary gets 5 checks + 2 tests (#16). No dimension read a schema-1→5 migration path — the memo's named highest-risk unexamined area (R-34). No failure-observability surface exists — no log, no crash record — though the project's own conventions require one (R-33). Docs drift: `CLAUDE.md:9` says "~4,650 lines" (actual 6,651); `CLAUDE.md:11` and `README.md:162-173` describe a two-module build and omit `api.mjs` (the module that once shipped entirely missing while 64 checks + 59 tests stayed green); README:138 claims a Chromium proof that is impossible at HEAD (R-23). A stray U+0000 at `core.mjs:816` makes ripgrep treat the settings-schema module as binary, disabling the repo's own re-grep-after-edit safeguard (R-15).

**The single unblock:** `npx playwright install chromium` (or set `CHROME_PATH`). Converts `verify-extension.mjs` from "green having proven nothing" into a real gate; unblocks ~18–22 live assertions (the only proofs that DNR blocks anything, that `LOCATOR_PROBES` still match live Kick, that filtering does not fail open), the `runtime.js` split, and ROADMAP Next items 1/4/5 + `Roadmap_Blocked.md` items. Never attempted. This is an environment action a coding agent can run.

## Rejected Ideas

Do not re-investigate — each with reason and source:

- **chrome.tabs "import open tabs"** — needs the dropped `'tabs'` permission + triggers CWS "read browsing history" warning; R-19/R-27 deliver the same UX permission-free. (`manifest.json` holds only `['storage','declarativeNetRequest']`.)
- **Inserting the `[emote:id:name]` wire token or id** — renders a locked emote without entitlement = entitlement bypass; hard-forbidden. Plain name only. (README:114; api.mjs:481-482.)
- **Auto-send in any form** (synthetic Enter, send-button click, POST, embedded-chat insertion) — crosses read-only into writing; multi-stream chat is read-only by design. (README:105; runtime.js:2369.)
- **Off-origin grid / companion-site model** (KickTheater architecture) — platform-hostility death pattern; on-origin embeds are the moat. (drupal #3155349, react-player #904.)
- **7TV / third-party emote federation** — conflicts with the same-origin privacy posture; ship as an **explicit documented decision, not silence.** (7TV Kick module; jakubn11.)
- **Full list virtualization for picker/organizer** — overkill at 2,400, fights find-in-page; FFZ deliberately avoids it (IntersectionObserver sections instead). Superseded by R-18. (FFZ emote_menu.jsx.)
- **Fuzzy-search dependency** (Fuse.js-style) — dependency violation; prefix+substring+usage covers the field standard. (R-25.)
- **Emote Bar+ hold-to-spam / turbo / pyramid** — write automation; violates read-only. (Kick Emote Bar+, CWS.)
- **`setRangeText` / synthetic `beforeinput` as insertion mechanism** — `setRangeText` is input/textarea-only; dispatched `beforeinput` is untrusted and runs no default action (only `click()` does). `execCommand('insertText')` is the surviving mechanism. (MDN; WHATWG DOM.)
- **Raw `textContent`/`innerHTML` fallback for insertion** — framework re-render desyncs visible text from editor model; fail loudly instead.
- **`window 'storage'` events as userscript-build cross-tab transport** — GM storage fires none; superseded by R-19's BroadcastChannel. (metadata.txt:12-18.)
- **Player-adjacent mount for the channel add button** — volatile player DOM, breaks in theater/focus; header testid is stable and check.mjs-gated. Superseded by R-07.
- **7TV-style zero-width emote rendering** — 7TV-ecosystem convention absent from native Kick; only the defensive host-filter survives (folded into R-16). (BTTV #5925.)
- **MessageFormat 2 / `Intl.MessageFormat`** — TC39 stalled at Stage 2; adopting MF2 means vendoring an ICU parser = a dependency in spirit. Use `Intl.PluralRules` (Baseline 2019). (TR35; tc39 proposal-intl-messageformat.)
- **Reference Target for cross-shadow ARIA** — Chrome-151-only, absent on Firefox MV2; keep each widget inside one shadow root or use element-reflection IDL. (whatwg/dom #1353; chromestatus 5188237101891584.)
- **Per-tile quality capping across the player origin boundary** *(prior-research settled)* — the player is a cross-origin embed; capping cannot reach across it. Settled; do not reopen.
- **AdGuard/uBO stitched-ad rule reuse** *(prior-research settled)* — no such rule exists: kick.com coverage in uAssets `filters.txt`/`unbreak.txt` and AdGuard Base is literally zero as of 2026-08-16; there is no upstream to defer to.
- **Worker-source-rewrite ad scrubbing** (vaft-style) — WASM-blocked on IVS + entitlement manipulation the project forbids. (deepwiki pixeltris/TwitchAdSolutions.)
- **TTV-LOL-style remote proxy** — remote code; disqualified. (younesaassila/ttv-lol-pro.)
- **20-stream grids** — MULTISTREAM_MAX=9 by design; embed/auth/perf ceiling. (core.mjs:1231.)
- **jsdom / happy-dom / fast-check / Node built-in `localStorage`** — deps (21/7/`pure-rand` transitive) or throws without `--localstorage-file` on Node 26; keep the `vm`-based hand-rolled stub. (registry.npmjs.org; nodejs #61709.)
- **Plugin / add-on ecosystem** — consciously excluded: FFZ's addons.json + dynamic script injection and Chatterino's Lua runtime are both remote-code loaders that the no-remote-code rule forbids; a single-author zero-dep mod's only safe extension point is the internal module contract (requires-ordering, namespaced settings paths, real unload), not a third-party loader.
- **RTL / bidi locale support** — consciously excluded for now: the three shipped locales (en/es/pt) are all LTR and no RTL locale is planned; revisit only if one is added, at which point `dir` handling and logical CSS properties become the work.

## Open Questions

Only items that block correct prioritization/implementation and need **live validation** (no Chromium on this machine — R-01 unblocks these):

1. **Insertion backend probe order (R-17/R-25).** Does `[data-testid="chat-input"]`'s root still expose `__lexicalEditor` to page-world scripts, and does `document.execCommand('insertText')` return true and update Kick's editor model? (NipahTV suggests yes.) The fallback ladder ends at the always-conforming picker-click backend, so the popup/ranking layers can be built first regardless.
2. **Kick's native Lexical suggester DOM (R-25).** Current selector for the `chat_emote_suggestion_list` transformer's popup, for the conflict-ladder "don't-trigger / CSS-hide" levels.
3. **Header/card markup drift (R-07/R-19).** Are `[data-testid="kicks-top-nav"]` and `[data-testid="livestream-results-card"]` still current for the add-button and card-chip mounts?
4. **Multi-embed performance (R-07).** Performance and authenticated quality levels with 4–9 Kick embeds in one page under the new one-click flows (Kickplex proves viability, not limits).
5. **GM-storage cross-tab freshness (R-19).** Read-back freshness across tabs for the read-merge-write path (Tampermonkey #2123, Violentmonkey #1214/#1490) — determines whether the `GM_addValueChangeListener` grant is worth adding or open-time re-sync alone suffices. Also: whether `kick.com` and `www.kick.com` (distinct origins, both matched) coexist in practice for BroadcastChannel/localStorage.
6. **IVS player-instance page-world reachability (R-09).** Does Kick expose its IVS Web Player instance to page-world scripts, and does it emit `AD_BREAK_STARTED/ENDED`, `AD_CREATIVE_STARTED`, `AD_TIME_UPDATE` (with pod/creative durations) on that instance? This is the entire feasibility gate for read-only ad-break observability.
7. **Realtime harvest URL liveness (R-06).** Confirmed 2026-08-16 that `files.kick.com/emotes/{id}/fullsize` serves anonymously (PNG + animated GIF); still needs a live check that crafted `[emote:999999:Fake]` frame tokens fail the one-shot `Image()` load as designed (the negative-cache validation that keeps untrusted frames from burning cap slots).
8. **Read-only Drops endpoint reachability (R-28).** Is a read-only Drops campaigns/progress endpoint reachable with the user's own session, or is Drops state only available through a write/claim path? Determines whether R-28 is buildable read-only.

**Needs operator decision (not live validation):** Tab/arrow/Enter capture while the autocomplete popup is open (contextual editing keys vs the no-new-shortcuts rule — mouse-only click-to-accept is the conforming default; keyboard nav ships only on explicit sign-off); and whether the insert-into-input setting defaults off with copy-name-only for the first release.
