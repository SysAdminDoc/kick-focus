# Research — Kick Focus
Date: 2026-08-17 — replaces all prior research (prior passes: 2026-08-15 against v1.5.0, 2026-08-16 against v1.9.0; every headline opportunity the 2026-08-16 pass named — R-01..R-37 — is drained or in `Roadmap_Blocked.md`).

**Scope of this pass.** Repo, build, gates and live behaviour were re-verified directly against v1.20.0 on 2026-08-17, including two full runs of the live browser gate against real Kick. External research covered the Kick platform (2025–2026 product surface), the browser-extension threat and policy landscape (2025–2026), and web-platform capability status (Baseline/BCD/vendor release notes). The **competitor sweep was not re-run** — the account's weekly research budget was exhausted mid-pass — so the Competitive Landscape section below is inherited from the 2026-08-16 pass (494 sources) and is labelled as such. Nothing in it is presented as newly verified.

## Executive Summary

Kick Focus at v1.20.0 is a zero-dependency, single-author kick.com client mod (123 commits) that builds four artifacts from one hand-rolled concatenation of seven ES modules — a userscript, an MV3 Chromium package, an MV2 Firefox package, and two zips — with no bundler, no `node_modules`, and no lockfile. It ships a shadow-DOM settings centre (5 pages, ~90 settings), a schema-8 emote library in IndexedDB behind a scored storage provider, a nine-tile on-origin multi-stream grid, page-realm and DNR ad defence, same-origin session-inherited reads of Kick's own endpoints, and es/pt localization. Every P0 the 2026-08-16 pass raised is fixed: the bridge fetch is pinned, inbound settings are schema-reduced, companion presence is proved by nonce round-trip, the GM blocklist fetch is `anonymous: true`, and `STORAGE_STORES` (`src/core.mjs:2663`) is now the single store registry that export/reset/labels all derive from. Its strongest current shape is exactly what it was built for: a read-only, fails-closed API posture with drift detection that reads the runtime's own probe list, and a live gate that genuinely executes the product.

The highest-value direction is **restoring trust in that gate before adding anything to it.** The gate is red at HEAD, and the failure is a shipped feature that is dead on the route most users land on. Then close the two roadmap items whose stated blockers have quietly expired, then take the 2026 platform wins and the one real accessibility failure.

Top opportunities, in priority order:

1. **Card actions render nothing on Kick's Home route.** Live gate, 2026-08-17: `a discovery card can be collected into the grid without opening it — no card chip rendered on this page` while 27 cards scored. The same run against `https://kick.com/browse` passes (`chip for davooxeneize`). Favourite, Not-interested and the multi chip all hang off the same early return in `applyCardActions()` (`src/runtime.js:2257-2259`), so all three are gone on Home. The DOM-drift gate cannot see it: it checks that probe *hooks* resolve, not that data *derived* from a hook survives. (R-38, P0. Verified.)
2. **The live gate reports route-shaped absence as FAIL for some checks and SKIP for others.** Against `/browse` it emits four failures that are not defects — `library is empty on this profile` ×2, `no video on this route`, and the emote-typing check — while the Poor-mode check on the same run correctly SKIPs with a reason. `release:check` and any non-default target are therefore unusable as a signal. (R-39, P0. Verified.)
3. **v1.20.0 is built, committed and shipped-shaped but never tagged or released**, and `README.md:147` still claims "51/51 live checks pass … (2026-08-16)" when HEAD runs 54 checks with 2 failing. Latest GitHub release is v1.19.0; latest tag is v1.19.0. (R-40, P0. Verified.)
4. **The translated interface carries no `lang`.** Selecting Español or Português localizes ~200 strings inside Kick's `<html lang="en">`, and nothing anywhere in `src/` sets `lang` on the Kick Focus root or shadow host (only `src/extension/popup.html:2` has one). That is a WCAG 2.2 SC 3.1.2 *Language of Parts* (Level AA) failure on the one product in this space that ships an accessibility page and measured 326 controls for AA conformance. (R-41, P1. Verified.)
5. **The Firefox package hands kick.com a per-install supercookie.** `manifest.firefox.json` declares `web_accessible_resources: ["content/kick-focus.js"]` and `bridge.firefox.js:19-21` injects it by `src`, putting `moz-extension://<per-install-UUID>/…` into the page DOM where any Kick script can read it. Firefox's extension UUID is randomised per install and stable for its life — a tracking identifier that survives cookie clears. Chromium adopted resource-UUID randomisation in Aug 2024 and MV3 offers `use_dynamic_url`; MV2's flat array has neither. The MV3 package is unaffected (no `web_accessible_resources`; it uses `world: "MAIN"`). (R-42, P1. Verified.)
6. **Neither background script validates message senders.** `background.js:33` and `background.firefox.js` act on `kick-focus:fetch-blocklist`, `:telemetry-preference` and `:reset-count` with no `sender` check. GitHub Security Lab names missing sender validation as one of the three canonical extension vulnerability classes. Exposure today is low (no `externally_connectable`, one content script), so this is defence-in-depth — but it is the cheap half of the class the bridge already fixed. (R-43, P1. Verified.)
7. **The bundle is on a collision course with Violentmonkey's injection ceiling.** `dist/kick-focus.user.js` measured across tags: v1.14.0 612,899 B → v1.17.0 695,234 B → v1.19.0 738,834 B → HEAD 763,775 B — about +25 KB per release. Violentmonkey 2.47.0+ only gives real `document-start` under MV3 Chromium in "Alternative page mode", which the project's own README records as advisory-limited to ~1 MB. At the current rate that is ~11 releases away, and the failure mode is silent late injection, not an error. No gate measures artifact size. (R-44, P1. Verified size trend; ~1 MB limit is Likely, needs live validation.)
8. **Two `Roadmap_Blocked.md` items are no longer blocked.** R-24 (userscript auto-update) was blocked on "the repo is private — a private raw URL 404s for every installed script"; `gh repo view` reports `"visibility":"PUBLIC"` as of 2026-08-17. The Firefox companion live proof was blocked on "no Firefox installation exists in this checkout"; Mozilla Firefox 153.0 is installed at `C:\Program Files\Mozilla Firefox\firefox.exe`, and Firefox 128+ supports WebDriver BiDi `webExtension.install` for temporary unsigned add-ons. (R-45, R-46, P1. Verified.)
9. **Document Picture-in-Picture became cross-engine in 2026** — Chrome 116, Firefox 151 (2026-05-19 release notes), no Safari. A real always-on-top window that renders arbitrary DOM is the single largest capability unlock for a multi-stream/chat mod since the Navigation API, and no competitor in the Kick space ships it. (R-53, P2. Verified.)
10. **Kick leaves an entire class of user pain unserved: expiry.** VODs live 7 days (unverified) / 30 days (verified), Kick ships **no download affordance for anyone including the broadcaster**, and creators can delete with one click. An entire third-party industry exists to service this. A read-only "this VOD expires in N days" surface reads an endpoint the page already calls. (R-49, P2. Verified against Kick's own help docs.)

## Product Map

**Core workflows (v1.20.0).**
- **Restyle + focus** — one shell over Kick's desktop DOM; Standard/Theater/Focus; Auto/Compact/Dropdown/Hidden discovery rail; 14 named Kick controls hideable by CSS only (`HIDEABLE_ELEMENTS`, `src/core.mjs:127`); panic switch restores native Kick without reload.
- **Emote library** — schema-8 platform-prefixed records in IndexedDB behind a priority-scored provider (`src/storage.mjs`), sourced from the native picker, live chat frames, the current-channel catalog, and on-demand channel browsing. Favourites shelf, custom groups, Kick-edit provenance, usage-ranked "most used"/"recent" shelves, windowed rendering, colon autocomplete (mouse-accept only), hover card, Copy name / Type in chat, JSON export/import.
- **Entitlement, stated not inferred** — v1.20.0's headline: an authenticated `/emotes/{slug}` read returns every set the account owns, so ownership is Kick's own statement. Reach and ownership are modelled independently (`usableEverywhere` / `usableHere`, `src/api.mjs:557-569`).
- **Multi-stream** — ≤9 channels in one on-origin grid of Kick's own embeds, audio/chat follow focus, named layouts, shareable `?kf-multi=` links with Undo, cross-tab convergence over BroadcastChannel + storage re-read, one-click add from cards and open tabs.
- **Content/ad defence** — page-realm `fetch`/XHR/beacon/element hooks + `/playback` ad-flag rewrite; companion adds `declarativeNetRequest` (block-action only, `initiatorDomains: ["kick.com"]`, no `modifyHeaders` — verified against `dist/extension/rules/ads.json`).
- **Quality, uptime, rewards** — session-key quality memory and highest-offered-rung start; a player-corner uptime chip from `livestream.start_time` with a schema.org `VideoObject` fallback; opt-in daily-reward auto-claim scheduled from Kick's own countdown and the 20:00 rollover.

**Personas.** Privacy-and-calm desktop viewer; emote collector / power-chatter; multi-channel viewer. No mobile, no auth flows, no writes beyond an explicit follow-gate and Kick's own claim button.

**Platforms & distribution.** Desktop Chromium (userscript + MV3) and desktop Firefox (userscript + MV2). Node ≥24.19. Public MIT repo `SysAdminDoc/kick-focus`, `main` protected, no CI by policy, releases v1.14.0–v1.19.0 with all three artifacts attached, 0 stars, no store listing. The userscript is the only artifact that reaches Windows/macOS users unassisted.

**Key data flows.** 12 registered stores (`STORAGE_STORES`, `src/core.mjs:2663`) across localStorage/GM and IndexedDB; page↔isolated-world DOM-event bridge with a nonce presence handshake; realtime WebSocket for chat; same-origin `/api/v2` reads carrying the page's own `session_token` as a bearer on Kick origins only.

## Competitive Landscape

**Inherited from the 2026-08-16 pass — not re-verified on 2026-08-17.** Dates are as recorded then; treat install counts and version numbers as at least one day stale and re-check before acting on any of them.

- **NipahTV** (Kick; userscript + Chrome + Firefox from one TS source, esbuild+Sass, Dexie) — *does well:* six versioned IndexedDB migrations and favourites keyed `[platformId+channelId+emoteHid]` with `orderIndex`; proves `execCommand('insertText')` works on Kick's editor. *Learn:* nothing outstanding — Kick Focus adopted the `platformId` prefix in schema 8 and the provider abstraction in v1.17.0. *Avoid:* Dexie is a dependency; borrow shape only.
- **FrankerFaceZ** — *does well:* `src/settings/providers.ts` priority-scored user-switchable storage providers with a `quota-exceeded` event and BroadcastChannel sync — the pattern `src/storage.mjs` now implements. Its **settings search across all pages** remains the one FFZ affordance Kick Focus has no equivalent of, and Kick Focus now carries ~90 settings across five pages. *Learn:* the settings search (R-48). Its picker has **no recency/most-used ranking** (FFZ #971, #1725 — requested, never delivered), a gap Kick Focus closed in v1.17.0. *Avoid:* the addons.json dynamic-script loader (remote code).
- **7TV** — *does well:* the field-standard colon autocomplete. *Learn:* its Kick support runs on an unversioned 2025 nightly against a 2026 site (no tagged stable since v3.1.6, 2025-03-04) — the opening for a maintained, drift-aware alternative is still open, and Kick Focus's live drift gate is the concrete expression of it. *Avoid:* third-party emote federation conflicts with the same-origin posture — ship as a documented decision, not silence.
- **BetterTTV** — *learn:* the `files.kick.com` vs `cdn.7tv.app` host-filter lesson (BTTV #5925) that keeps a chat scan from ingesting another extension's injected imgs.
- **Chatterino** — *does well:* a user-facing filter DSL over `author.*`/`message.*`/`channel.*`. Its documented tab-completion case-collision bugs (#1962/#3440) are the tests `rankEmoteCompletions` (`src/core.mjs:638`) was written against. *Avoid:* a Lua runtime (remote code).
- **Kickplex / KickTalk / Kickerino / MultiKick** — *learn:* Kickplex moved multi-view past tiles to unified cross-channel chat, DVR rewind and PiP — the closest thing to a rival for the grid, and the reason Document PiP (R-53) matters. Kickerino is an early-warning system for Kick API churn. Every one of them carries pnpm/Vite/esbuild/Tauri/Electron; the dependency-free three-artifact build is still uncontested.
- **PureKick / Kick-Ad-Blocker** (PureKick: 20,000 users, 4.8/5, v10.2.1 on 2026-08-15) — *learn:* mainstream filter lists **still do not cover kick.com** (uAssets #33256 and AdguardFilters #233048 both declined), so there is no upstream to defer to and no inherited breakage reports. *Avoid:* naive `[data-testid*="ad"]` selectors, which false-positive on Kick's `identity-badge-subscriber` markup (lurkloot #242).
- **Kick Quality Enforcer** and three Greasyfork scripts — *learn:* quality persistence is the most independently re-implemented Kick need, and Kick Focus's v1.19.0 measurement (the player reads a bare height from `sessionStorage['stream_quality']`, not the menu label) is a correction none of them appear to have made.
- **multitwitch / StreamGrid / viewgrid / KickTheater** — *learn:* the add-flow is the field's #1 complaint, which is what the card chip and "Add open tabs" answer — and which R-38 currently breaks on Home. *Avoid:* off-origin grids are the platform-hostility death pattern; on-origin Kick embeds are the moat.

**What changed on the platform side since that pass** (2025–2026 Kick product surface, verified against Kick's own help centre and newsroom this pass): Kick Ads launched 2026-08-04/06 with pre-roll and mid-roll, after unannounced testing in May 2026 that drew public creator backlash — which validates `README.md:155`'s "it cannot remove Kick's in-stream video ads" as the honest position, not a hedge. Four *separate* loyalty systems now exist and Kick presents them as unrelated: Drops (game partners, Nov 2025), Daily Rewards (watch-1h roulette, platform-wide 2026-07-01), Kick Levels (passive global watch-time badges, ~2026-06-02, off by default), and Channel Points (per-channel, Apr 2025) with Predictions on top (May 2025). Clips went to 3 minutes with a `[c]` hotkey on 2026-02-10, and Kick's own errors page documents clip capture-window mismatch, silent save failures and greyed-out buttons as known issues. Kick now ships viewer-side gambling/hot-tub category filters natively.

## Security, Privacy, and Reliability

All 2026-08-16 P0s are closed — re-verified in code this pass. New and residual findings:

- **[P1] Firefox MV2 extension-UUID leak (Verified).** `src/extension/manifest.firefox.json` `web_accessible_resources` + `src/extension/bridge.firefox.js:19-21` put `moz-extension://<UUID>/content/kick-focus.js` in the page. The UUID is per-install, permanent, and readable by any script on kick.com — a supercookie on a product whose settings copy sells privacy. Removing the element `on load` (line 22) does not help: the URL is already in the DOM and in `performance.getEntriesByType('resource')`. The only leak-free shape is fetching the bundle text from the extension and injecting it inline, which trades the leak for a hard dependency on Kick continuing to ship no CSP (confirmed absent this pass). Document the trade whichever way it goes. (R-42.)
- **[P1] No `sender` validation on runtime messages (Verified).** `src/extension/background.js:33`, `src/extension/background.firefox.js`. Note the documented ceiling: a compromised renderer can spoof `MessageSender.id`/`.url`, so this hardens against other *extensions*, not against a compromised renderer. (R-43.)
- **[P1] `@connect *` in `src/metadata.txt:19` (Verified, mitigated).** The credential leak is closed (`anonymous: true`, `src/runtime.js:4212`) and `blocklistUrl` is https-validated at the bridge. What remains is that the userscript still asks every user for unrestricted cross-origin fetch at install time, which is the broadest permission in the manifest and the hardest to justify in a store listing. (Folded into R-58.)
- **[P0-adjacent] Silent feature death is the live failure mode, not crashes (Verified).** R-38 is the second instance this month of a whole feature disappearing with every gate green — the first was `[data-kf-player] video` never matching, which killed three features at once (`CLAUDE.md`, 2026-08-17). The pattern is identical: a hook resolves, something *derived* from it does not, and no gate asserts the derived value. The drift gate needs a second tier that asserts derived data, not just probe resolution.
- **Distribution-channel takeover is the dominant 2026 threat to a project this shape (Verified, external).** Every high-confidence 2025–2026 incident is an attacker publishing under a trusted identity, not a code flaw: the Dec 2024 CWS OAuth-consent phish (17 extensions, Sekoia 2025-01-22), the Feb 2025 compromised-developer campaign (16 extensions / 3.2M users, GitLab), the **Feb 2025 Greasy Fork inactive-account takeover** that injected payment-scraping code into two Waze scripts, ShadyPanda's sleeper updates (Dec 2025, 4.3M users), and the Feb 2026 QuickLens ownership-transfer attack (7,000 users). This bears directly on R-45: wiring `@updateURL` at a raw GitHub URL turns the GitHub account into a distribution channel pointed at end-user machines. Hardware-key 2FA, no listing transfers, and a sha256 `update_hash` in the Firefox `updates.json` are the mitigations.
- **DNR discipline holds (Verified).** `dist/extension/rules/*.json` are `{"type":"block"}` only with `initiatorDomains:["kick.com"]`; no `modifyHeaders` anywhere. DNR CSP-stripping is the most consistent malicious signature across GitLab Feb 2025, Palant Feb 2025 and QuickLens Feb 2026, and CVE-2026-0628 (8.8, "Glic Jack") showed DNR reaching privileged WebView surfaces. Keep this as a mechanical review rule; a gate asserting no rule action other than `block` would make it permanent.
- **Chrome Web Store policy changes land 2026-08-01 (Verified).** The 2026-07-01 policy update tightens **Limited Use** (collection restricted to what is strictly necessary to the disclosed single purpose) and **Disclosure** (prominent disclosure of all collection, plus notification of post-install changes). Kick Focus collects and transmits nothing, so it clears both trivially — but the **single-purpose** rule is the live risk for a mod that bundles layout, ad defence, an emote library and a multi-stream grid. Firefox's policy (updated 2026-04-30) additionally restricts the `userScripts` API to script-manager extensions only, which forecloses that injection route on AMO.
- **Reliability, unchanged and healthy.** Import is transactional and refuses a forward schema (`src/core.mjs:1956`); reset keeps the library and clears the registry; export derives from `STORAGE_STORES`; the storage provider falls back cleanly when IndexedDB refuses. No regression found.
- **Observability is adequate and deliberately local (Verified, no action).** The About page carries an error log with a copy action (`src/runtime.js:7264`), a last-crash summary, per-cycle apply cost, a protection log, and live-read diagnostics; `sanitizeErrorMessage()` (`src/core.mjs:802`) strips query strings and tokens before anything is displayed or copied. Nothing is transmitted, which is both correct for the posture and what makes the project clear the 2026-08-01 CWS Limited Use rule without changes. No telemetry item is proposed, in either direction.
- **Multi-user is not a concept here and should not become one (Verified, no action).** State is per browser profile with no accounts, no sync and no profile switching; the correct portability mechanism is the existing export/import, which now covers all 12 registered stores. Settings *profiles* (named preset sets) were considered and dropped — they would multiply the migration surface across 12 stores for a single-user desktop mod.

## Architecture Assessment

1. **`runtime.js` grew back past the split.** 9,243 lines (`src/runtime.js`) — the v1.17.0 refactor took it from 9,012 to 7,988 by extracting `live.mjs` and `multistream.mjs`, and six releases have more than refilled it. `CLAUDE.md:9` still says "~7,990 lines". The extraction pattern is proven and the next obvious seams are the settings UI renderer (~`:6760-7400`) and the emote library/organizer surface, both of which are pure-enough to take a `host` factory like the two existing modules.
2. **The drift gate checks hooks, not derived data.** `compatibilitySnapshot()` (`src/compatibility.mjs:242`) asserts that each named probe resolves and reports fall-throughs. It passed on the run where R-38 failed, because `card:card-testid` resolved fine — what died was `cardPath()` → `cardSlugFromPath()` downstream of it (`src/runtime.js:2133`, `src/core.mjs:2361`). A second tier asserting that a hook still *yields its value* (a card yields a channel slug; a player container is not the video) closes both this month's silent-death bugs.
3. **The live gate conflates "not applicable here" with "broken".** `record()` (`scripts/verify-extension.mjs:137`) has two outcomes; the surrounding code hand-rolls SKIP in some places (`if (reachedKick)`, the Poor-mode check) and returns `{ok:false, why:'…'}` in others for the identical situation. Give `record()` a third `skip` outcome with a required reason, and every probe's precondition becomes declarative instead of a convention. (R-39.)
4. **`live.mjs` is the least-covered module at 57.34% lines / 48.72% functions**, and the uncovered ranges are the ones that matter: `connectRealtime` (`:381-442`), `onRealtimeFrame`/`onRealtimeChatMessage` (`:453-496`), badge render and replay (`:543-606`), deletion annotation (`:620-650`). It was extracted specifically to be testable through a `host` factory; the boundary exists and is simply not being used for the realtime half. (R-47.)
5. **No artifact-size budget.** Three artifacts, a documented ~1 MB injection ceiling on one distribution channel, +25 KB/release, and 159 checks in `scripts/check.mjs` — none of which measures a byte count. (R-44.)
6. **Coverage exemptions are honest but load-bearing.** `test/coverage.test.js` documents `runtime.js` and the three extension entry points as unreachable with real reasons and asserts the exemption list stays truthful in both directions — good design. It also means 9,243 of ~13,000 source lines are covered only by `boot.test.js`, the artifact greps, and the live gate, which is precisely why the live gate being red matters more here than in a project with broad unit coverage.

**Docs drift.** `README.md:147` claims 51/51 live checks (actual: 54 checks, 52 passing at HEAD). `CLAUDE.md:9` says `runtime.js` is ~7,990 lines (actual 9,243). `Roadmap_Blocked.md` carries two items whose blockers no longer exist (repo privacy; no Firefox install). The `design/` mockups still carry C2PA credentials naming "OpenAI Media Service API" — deliberately left intact, and correctly so.

## Rejected Ideas

- **A light theme.** Kick is dark-only; a light Kick Focus shell would fight the host site everywhere it does not fully cover. The three existing surfaces (Studio/OLED/Slate) plus `strongContrast` and `forced-colors` support are the right answer. (Global convention says "where practical" — here it is not.)
- **Storage Buckets API.** Chromium-only since Feb 2024, no Firefox, no Safari; `src/storage.mjs` already solves the same problem with IndexedDB + a scored provider. (webstatus.dev.)
- **Region Capture / Element Capture** for a clip or thumbnail feature. Both Chromium-only and both require `getDisplayMedia` screen-capture permission — unacceptable for an unobtrusive mod, and Mozilla's standards position on Element Capture is explicitly negative (mozilla/standards-positions#857).
- **`interestfor` / interest invokers** for the emote hover card. Chrome/Edge 142 only, no Firefox, no Safari, and the spec is still an unmerged WHATWG PR (#11006). Hand-rolled hover intent stays.
- **Scroll-driven animations, cross-document view transitions, `speculationrules`, LoAF.** Each is Chromium-only or Firefox-Nightly-only as of 2026-08, and none earns a divergent code path in a two-engine target.
- **`chrome.userScripts` as an injection route.** Mozilla's 2026-04-30 policy restricts the API to script-manager extensions only; using it to extend the mod itself is a listing violation on AMO.
- **An OAuth app against Kick's public API** (docs.kick.com, launched Feb 2025 with webhooks). It would replace "reads the session the browser already has, same-origin, read-only" with "holds a token and talks to Kick as itself" — a strictly worse trust posture for the same data, and Kick's developer terms bar apps that interfere with ads.
- **A plugin/add-on system.** Every mechanism that makes third-party code loadable is remote code by another name; FFZ's addons.json loader is the cautionary example and the Feb 2025 Greasy Fork incident is what it looks like when the channel is compromised.
- **Full list virtualization** for the picker/organizer. Superseded by the v1.17.0 windowed renderer (240 of 900 tiles measured live); FFZ and 7TV both deliberately avoid windowing at this scale.
- **Additional locales beyond es/pt.** No evidence found this pass for a third locale's demand; the correct next i18n work is making the two existing ones programmatically announceable (R-41), not adding a third.
- **Mobile support.** Explicitly deferred in `ROADMAP.md`; Kick's own mobile app is a separate product with a different feature set, and the settings surface is desktop-shaped by design.
